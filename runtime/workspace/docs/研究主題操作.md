# 研究主題：Agent 操作流程

這個流程只在使用者明確要求研究時使用。先在 workspace 以設定中的 Python 執行：

```text
tools/brain.py research list
```

先把現有主題、狀態和可接續工作讀回給使用者。不要從一般問題猜測研究主題、建立背景排程或外部搜尋。

要建立新主題時，先一次收齊：主題名稱、研究目的、範圍、焦點、證據標準、輸出形式、分類方式、總量上限和每次可用的研究額度。使用者確認後，先執行 `tools/brain.py research-program next --topic-id <topic-id>`：主題尚未存在時，它唯讀列出 `init-topic` 的全部欄位、可選值和哪些要使用者決定（不替使用者填值、不寫入任何檔案）。再以 `tools/brain.py research-program init-topic` 建立 **manual_research** 主題；不得猜旗標；PUBLIC 不支援 `scheduled_research`、排程設定或排程執行。

若題材需要判斷「原站確有互動、而非只是一張圖片」，建立主題時才加入 `selection_contract`。它必須列出版本、該題材自己的 criteria、是否需要原站互動及重現；不能把別的題材的美感或分類條件照搬。每個合格個案要把每項 criteria 的判斷、可讀的截圖證據、原站互動前後狀態及重現對照一起綁定。AI 可協助找證據，但「是否值得學習」仍由人判斷，不能由分數自動決定。

若研究目標是學習原作的**核心方法**，`selection_contract` 必須另設 `learning_alignment_required: true` 和對應的 `reproduction_criterion`。個案必須逐項列出：來源依據、核心機制、本地實際結果、不採用的偷工捷徑，以及由受限瀏覽器動作記錄的實際狀態改變。只有每個已選核心機制都被本地動作記錄逐一覆蓋，才可標示為「方法已驗證」。頁面能開、截圖、hash、成功 exit code 或普通靜態版面都不能取代這項證據。

需要原站互動證據時，先在已建立的 workspace 內檢查瀏覽器擷取能力：

```text
node tools/case_reproduction_capture.js --check
```

若未就緒，Agent 只可依隨包 `tools/package.json` 的鎖定版本，在 `workspace/tools` 安裝 Node 依賴和 Chromium，再重跑檢查；不可改用靜態截圖並宣稱已驗證互動。擷取時只可用已審閱的來源 URL、單一可見目標、有限 scroll／wait／狀態斷言和截圖；不得把任意 JavaScript 或系統命令放進 request。`case_reproduction_capture.js` 會留下原站 URL、viewport、動作、前後狀態及 hash。空白頁、透明圖、被遮罩的目標、重複目標或沒有狀態改變都必須失敗。

若已接納個案其後被證明不合格，用 `tools/brain.py research-program withdraw-case --topic-id <topic-id> --case-id <case-id> --reason <reason>` 撤回合格資格。這不刪原來源、completion receipt 或舊證據；同一來源不可換 case ID 再次當作新來源。完成的舊 run 可以開始新的 run，未完成的 run 則必須先接續或處理。

若來源及 receipt 仍可保留，但後來發現「本地頁面能運行」被誤當成「已學會核心方法」，不可用撤回來釋放名額或重新算作新案例。改用 `tools/brain.py research-program mark-case-needs-revalidation --topic-id <topic-id> --case-id <case-id> --reason <reason>`：它保留原來源、receipt 和名額，禁止重播完成與再用該來源做方法應用，直到以來源綁定的新重現補足核心機制證據。

要續做時，先用 `tools/brain.py research inspect --topic-id <topic-id>` 與 `tools/brain.py research-program status --topic-id <topic-id>` 讀回；`tools/brain.py research-program next --topic-id <topic-id>` 會唯讀印出同一份額度摘要，以及按目前狀態已填好 topic、run、case、rail 指令的下一步命令，每走完一步再執行一次。`complete-case` 若省略 `--completion-receipt`，會從該案例綁定的已完成 rail 工作解析；找不到綁定仍須明確提供。`begin-run` 若省略 `--executor-model`，會採用 `brain.json` 的 `executor.model` 宣告（沒有宣告即記為 `unspecified`，不猜）。只有使用者明確要求某次研究，才按讀回的狀態建立／接續 run；每一步都保留來源、額度與完成證據。外部搜尋、下載、圖片或寫入一律按當前能力與使用者授權處理。

研究成果仍要通過同一入庫流程。一般研究可在 topic 的 `evidence_contract.asset_mode` 選 `knowledge_only`，以完整文字、分析、讀回和完成憑證正式入庫，不要求新資訊圖；`case_evidence` 仍保留原有原站證據及資格要求。這份研究設定不會自動把新材料、通知或任何其他產品加入工作區；背景排程只屬 OPS，並不包含在 PUBLIC。
